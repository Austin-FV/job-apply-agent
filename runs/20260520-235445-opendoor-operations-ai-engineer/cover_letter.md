This letter, the attached resume, and the form fields I just submitted were all generated by an agent I built called job-apply-agent (github.com/Austin-FV/job-apply-agent). I built it specifically because this role asks for someone who defaults to AI — and submitting a hand-typed cover letter felt like the wrong answer to that prompt.

Two architectural choices in the agent map directly to what this role is asking for. First: every resume bullet carries a Pydantic-validated `source_tag` that traces back to a specific entry in my profile.yaml. The LLM cannot emit a bullet that doesn't resolve to a real achievement — fabricated content fails schema validation before it ever reaches a PDF. That's schemas as data quality enforcement, not paperwork. Second: rather than building a Rippling adapter, a Greenhouse adapter, and a Lever adapter that each rot on the next ATS redesign, I hand a vision-aware browser to Claude with a checklist and applicant data, and one code path covers any ATS. Maintenance cost stays flat as I add target sites.

The JD asks for someone who can evaluate "build-vs-integrate decisions for AI tools and automation, with a bias toward scalable, maintainable solutions over one-off demos." That instinct is exactly what the single-code-path bet was. The same reasoning drove the 25-component Selenium framework I built at Express Scripts Canada — reusable architecture that QA engineers could extend without touching the core, rather than a pile of one-off scripts. gimmit, a VS Code extension I shipped, grounds commit messages in actual diffs via the Anthropic and OpenAI APIs — the same anti-hallucination reflex as the `source_tag` system, applied to a developer workflow surface. The full run artifacts for this application — scraped JD, resume JSON with source tags, the browser-use trace, and a GIF of the agent submitting the form — are committed in the repo.

Opendoor is one of the few companies where "AI isn't a side project" is a structural claim, not a recruiting line, and I want to build in an environment where that's the default. I'm looking to move from automation engineering into product-facing AI systems work, and this team — sitting at the intersection of operations, data, and AI engineering — is exactly where I want to go deep.
